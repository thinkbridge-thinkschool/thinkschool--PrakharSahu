------------------------------------------------------------------------------
Three separate rules caught the same violation, each from a different angle:

  Domain_depends_on_nothing_but_the_shared_kernel
      the layer rule -- Domain may see SharedKernel and nothing else

  No_module_reaches_into_another_modules_internals
      the module rule -- a cross-module edge must land on *.Contracts

  The_documented_cross_module_edges_are_the_only_ones
      the inventory -- the full graph is written down, and this is not in it

Overlap is deliberate. A single rule can be weakened by one well-meaning edit;
three rules stating the same boundary in different terms cannot all be softened
without somebody noticing what they are doing.

Footnote worth keeping: `dotnet remove reference` silently no-opped when handed
the path this script used, so an earlier capture showed the suite still red AFTER
the revert. The reference had to be stripped from the .csproj directly. A command
that reports success while changing nothing is the same class of problem these
tests exist to catch.
